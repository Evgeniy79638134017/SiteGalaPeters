# PROMPT_072_video_cdn  (ПРЕДУСЛОВИЕ: аккаунт Gcore от владельца)

## Контекст
TASK-072 (SPRINT-4, Вариант A): вынести hero-видео (и, опц., крупные изображения) на
глобальный CDN Gcore — чтобы Европа получала его с ближайшего edge, а РФ не теряла.
Видео — НЕ ПДн, раздача через CDN законна (PERF_ARCHITECTURE_PLAN §6). Подключение по
CNAME (поддомен cdn.gpeters.ru), без делегирования основного домена.
ПРЕДУСЛОВИЕ: владелец завёл Gcore-аккаунт и CDN-ресурс (origin = gpeters.ru/media или
загрузка файла), дал CDN-домен/URL. Если нет — BLOCKER в отчёт, не выдумывать.
Прочитай: CLAUDE.md, PERF_ARCHITECTURE_PLAN.md (§3.1, §4 вариант A, §7, §8),
src/components/sections/Hero.tsx.

## Цель
Видео отдаётся с Gcore CDN; московский /media остаётся рабочим резервом.
Готово = (1) src видео в Hero указывает на CDN-URL (https, поддомен cdn.gpeters.ru или
выданный Gcore); (2) видео играет и в РФ, и из ЕС (проверить curl/таймингом из доступных
точек; PageSpeed из ЕС — владелец/PM); (3) постер и фоллбеки работают; (4) старый путь
/media/hero-bg.mp4 НЕ удалять (мгновенный откат — вернуть src); (5) lint/tsc/build зелёные;
(6) замеры показывают ускорение видео для ЕС без регресса РФ.

## Вайб
Одна обратимая правка пути + проверка. CDN кэширует только публичную статику; /api и БД
не затрагиваются.

## Технические параметры
- CDN-домен/URL берётся из ENV или константы (легко заменить/откатить). https обязателен
  (нет mixed content).
- Не переносить на CDN ничего из /api; ПДн через CDN не ходят.
- Если CDN-домен на отдельном origin — проверить CORS не требуется для <video> того же
  типа (медиа), но убедиться, что файл отдаётся с корректным Content-Type/Range.
