# PROMPT_080_cookie_consent

## Контекст
TASK-080. На сайте нужен корректный механизм cookie-согласия под юрисдикцию РФ (152-ФЗ)
и EU-аудиторию (GDPR/ePrivacy). Полное обоснование и источники: siteGala/COOKIE_CONSENT_RESEARCH.md
(48 источников) — ПРОЧИТАЙ его перед работой, особенно разделы 3 (техника) и 4 (Вариант B).
Текущее состояние аналитики: ТОЛЬКО Umami (cookieless, без cookie, не идентифицирует) — баннер
её НЕ касается. Яндекс.Метрика и Google Analytics РЕШЕНИЕМ ВЛАДЕЛЦА (11.06.2026) ОТЛОЖЕНЫ —
их в этой задаче НЕ подключаем, но инфраструктуру готовим так, чтобы их потом включить одной
правкой. Формы уже имеют отдельный чекбокс согласия ПДн (TASK-013) — его НЕ трогаем и форму
баннером НЕ блокируем (cookie-согласие ≠ согласие-ПДн, см. отчёт §3.6).
Прочитай: CLAUDE.md, src/app/layout.tsx, src/components (структура), package.json.

## Цель
Готовый, реально работающий механизм cookie-согласия, который НЕ ломает сайт и готов принять
Метрику/GA позже. Готово =
(1) Подключена библиотека `vanilla-cookieconsent` (v3, MIT, self-hosted, без внешних SaaS).
(2) Клиентский компонент `CookieConsent` (use client), смонтирован в layout; рендерится ТОЛЬКО
    после mount (useEffect) → нет hydration mismatch и мигания (см. отчёт §3.4).
(3) Категории: `necessary` (enabled:true, readOnly:true — всегда вкл, нельзя отключить),
    `analytics` (opt-in, по умолчанию выкл), `marketing` (opt-in, по умолчанию выкл).
(4) Баннер на первом экране: равноправные кнопки «Принять все» / «Отклонить все» / «Настройки»
    (одинаковый вес/размер — требование EDPB, см. отчёт §2). Модалка настроек — тумблеры по
    категориям. Язык — русский (можно добавить en позже).
(5) Хранение согласия: cookie `cc_cookie`, `expiresAfterDays: 182` (~6 мес переспрос).
(6) Постоянная ссылка «Настройки cookie» в футере, открывающая модалку (для отзыва/изменения).
(7) ГОТОВНОСТЬ К ТРЕКЕРАМ, но БЕЗ их подключения: в колбэке `onConsent`/`onChange` оставить
    ПУСТЫЕ функции-плейсхолдеры `initAnalytics()` / `initMarketing()` с комментарием-TODO
    «сюда позже вставить Яндекс.Метрику / GA — грузить ТОЛЬКО при acceptedCategory(...)».
    Никакого кода Метрики/GA сейчас не добавлять.
(8) Umami НЕ трогаем (cookieless, согласия не требует) — если уже подключён, оставить как есть.
(9) Сайт и формы работают одинаково ДО и ПОСЛЕ любого выбора в баннере (необходимые cookie
    не блокируются). Форму отправки баннером не гейтить.
(10) lint/tsc/build зелёные; на проде баннер появляется один раз, выбор запоминается,
     ссылка в футере открывает настройки.

## Вайб
Аккуратная изолированная фича: один компонент + инициализация в layout + ссылка в футере.
Ничего в существующих секциях/формах не ломать. Библиотека делает тяжёлую работу — наш код
тонкий (конфиг + монтирование). Не изобретать свой баннер, не тащить SaaS (CookieYes/Cookiebot).

## Технические параметры
- cwd antiage-platform/. `npm i vanilla-cookieconsent`. Стили подключить из пакета
  (`vanilla-cookieconsent/dist/cookieconsent.css`) — импорт в компоненте или layout.
- Инициализация строго в useEffect (CookieConsent.run({...})) — никаких вызовов на уровне модуля
  и НЕ `beforeInteractive`.
- Тексты (RU): заголовок «Мы используем файлы cookie», описание — кратко: сайт использует
  необходимые cookie для работы; аналитические/маркетинговые — только с согласия; ссылка на
  «Политику в отношении файлов cookie» (страница из TASK-081, путь /cookie-policy).
- Конфиг категорий пример (адаптировать под API v3):
  necessary: { enabled:true, readOnly:true }, analytics:{}, marketing:{}.
- onConsent/onChange: если acceptedCategory('analytics') → initAnalytics() (плейсхолдер);
  аналогично marketing. Сами функции пустые с TODO.
- Footer: добавить ссылку/кнопку «Настройки cookie» → `CookieConsent.showPreferences()`.
