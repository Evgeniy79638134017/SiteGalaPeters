# PROMPT_071_nginx_cache

## Контекст
TASK-071 (SPRINT-4, Вариант A): ускорить отдачу на московском Nginx — кэш статики,
сжатие, HTTP/2 — БЕЗ риска для ПДн и без поломки сайта. Сервер: gpeters.ru
(89.108.76.118), Nginx из TASK-015 (конфиг — в REPORT_TASK-015). Прочитай: CLAUDE.md,
PERF_ARCHITECTURE_PLAN.md (§6 безопасность, §7 план, §8 риски),
.claude/reports/REPORT_TASK-015_2026-06-05.md, PERF_BASELINE (TASK-070).

## Цель
Кэш + сжатие + HTTP/2 на Nginx; РФ не замедлён, ПДн не кэшируются.
Готово = (1) HTTP/2 включён (`listen 443 ssl http2`); (2) gzip и (если доступен модуль)
brotli включены для text/css/js/json/svg; (3) proxy_cache для статики Vercel
(/_next/static, изображения, шрифты) с разумным TTL; HTML — короткий TTL или
microcaching, на выбор с обоснованием; (4) **`/api/` и `/media/` НЕ кэшировать**
(api — ПДн/динамика; media отдаётся отдельно); ответы с Set-Cookie не кэшировать;
(5) `nginx -t` ок, reload без ошибок, сайт и формы работают, /api/healthz=200;
(6) повторные замеры (как в TASK-070) показывают улучшение или паритет, не регресс.

## Вайб
Консервативно и обратимо. Сделать БЭКАП конфига перед правкой; любой шаг откатывается
возвратом бэкапа + reload.

## Технические параметры
- Перед правкой: `cp` текущего конфига в /root/nginx-backup-<дата>/.
- Кэш-зона в http-контексте; `proxy_cache_bypass`/`no_cache` для cookie и /api.
- Явно: `location /api/ { ... no cache ... }`, `location /media/ { ... }` без proxy_cache
  (или отдельные правила); статику Vercel кэшировать по Cache-Control от origin.
- brotli может отсутствовать в стоковом nginx — если модуля нет, не собирать из исходников
  (вне объёма), ограничиться gzip; отметить в отчёте.
- `nginx -t` обязателен перед каждым reload.
