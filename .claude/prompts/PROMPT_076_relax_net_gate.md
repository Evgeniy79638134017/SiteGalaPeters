# PROMPT_076_relax_net_gate

## Контекст
TASK-076 (фикс). Диагностика на живом браузере показала корень проблемы «видео не грузится
за рубежом/через VPN»: в Hero.tsx (из TASK-073) условие «медленная сеть» включает `3g`:
`["slow-2g","2g","3g"].includes(conn.effectiveType)`. Browser/VPN часто рапортует
effectiveType="3g" (грубая пессимистичная оценка Chrome, особенно через VPN и при задержке),
из-за чего `showVideo=false` → `<video>` НЕ монтируется вообще, видна только постер-картинка.
Подтверждено: innerWidth=2048 (десктоп), reduceMotion=false, но effectiveType="3g" → видео нет.
То есть выбор источника (TASK-075, Vercel→Москва) вообще не запускается. Прочитай: CLAUDE.md,
src/components/sections/Hero.tsx.

## Цель
Видео монтируется на нормальных и VPN-соединениях; постер-only остаётся только для реально
медленных сетей и saveData.
Готово =
(1) условие slowNet в Hero больше НЕ блокирует на `3g`: оставить блокировку только при
    `saveData === true` ИЛИ `effectiveType ∈ {"slow-2g","2g"}` (3g и выше → видео показываем);
(2) на десктопе с обычной/VPN-сетью (effectiveType "3g"/"4g", saveData=false) `<video>`
    монтируется и стартует выбор источника Vercel→Москва (TASK-075) как задумано;
(3) на узком экране (мобайл) и при saveData/2g — по-прежнему только постер (логику не ломаем);
(4) prefers-reduced-motion — без изменений (постер);
(5) lint/tsc/build зелёные; на проде в консоли проверить: при обычной сети видео-элемент
    появляется, currentSrc выставляется (Vercel, затем при таймауте — Москва).

## Вайб
Однострочная правка условия + проверка. Остальную логику Hero (постер, lazy на мобайл,
reduced-motion, таймаут-фолбэк) не трогать.

## Технические параметры
- cwd antiage-platform/. Изменить массив effectiveType: было ["slow-2g","2g","3g"] →
  стало ["slow-2g","2g"]. Прочее без изменений.
- Проверка на проде через DevTools/консоль: `document.querySelector('video')?.currentSrc`
  должен быть непустым на десктопе с нормальной сетью.
