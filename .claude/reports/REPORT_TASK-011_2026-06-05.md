## Проблемы / открытые вопросы

- Метод применения миграции изменён с `prisma migrate dev` на генерацию SQL из схемы
  (`prisma migrate diff --from-empty --to-schema`) + `prisma migrate deploy`. Причина: SSH-туннель
  Windows OpenSSH (`-L 15432→5432`) нестабилен — форвардер падал после первого же соединения,
  из-за чего `migrate dev` (создаёт shadow-БД, много соединений) рвался (P1017/P1001). `migrate
  deploy` использует одно короткое соединение и прошёл с первого раза без shadow-БД. Артефакт
  идентичен: каталог `*_init/` с `migration.sql`. Флаг Prisma 7.5: `--to-schema-datamodel` → `--to-schema`.
- Файл `migration.sql` приведён к LF; checksum в `_prisma_migrations` синхронизирован с LF-версией
  (Prisma считает SHA-256 байт файла; при `core.autocrlf=true` CRLF разошёлся бы с БД). Добавлен
  `.gitattributes` (eol=lf), staged-блоб = LF → checkout на сервере совпадёт с БД.
- Для первой миграции роли временно давался `CREATEDB`; после применения снят
  (`ALTER USER antiage_app NOCREATEDB`) — least privilege.
