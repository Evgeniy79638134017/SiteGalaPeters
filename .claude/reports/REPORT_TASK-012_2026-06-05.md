## Проблемы / открытые вопросы

- Фреймворк: выбран **Express 5.1.0** (скучно, стандартно, минимум зависимостей) вместо Fastify.
- Prisma 7.5: `new PrismaClient()` без опций бросает ошибку, а сгенерированный клиент использует
  wasm query-compiler без нативного движка → подключение требует **driver adapter**. Добавлены
  `@prisma/adapter-pg` + `pg`; клиент создаётся как `new PrismaClient({ adapter })`. Плюс: wasm+pg
  не зависят от платформы (нет нативного бинарника движка).
- Генерация клиента: пакет хранит **копию** `schema.prisma` (на сервере antiage-platform нет).
  Миграции этим пакетом НЕ запускаются — владелец схемы и миграций остаётся antiage-platform;
  при изменении схемы фронта копию нужно синхронизировать вручную.
- Сборка/деплой: `tsc → dist` локально, архив (без node_modules) через scp → распаковка на сервере →
  `npm ci --omit=dev` (postinstall `prisma generate` создаёт wasm-клиент на сервере). Поэтому `prisma`
  в dependencies (а не devDependencies), иначе generate не выполнился бы при `--omit=dev`.
- `npm audit`: в транзитивных зависимостях есть предупреждения; форсить fix не стал (риск ломки
  версий). Адресовать отдельной задачей при необходимости.
