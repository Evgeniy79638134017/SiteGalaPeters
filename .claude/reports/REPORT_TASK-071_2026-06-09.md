- **gzip:** новый `/etc/nginx/conf.d/perf-cache.conf` — `gzip_vary/gzip_proxied any/comp_level 5/min_length 256`
  + типы css/js/json/svg/xml/woff. **brotli — НЕ включён**: модуля нет в стоковом nginx
  (нет `.so` в `/usr/lib/nginx/modules`, пакет `libnginx-mod-http-brotli` недоступен в репозитории),
  сборка из исходников — вне объёма. Ограничились gzip (HTML и так приходит gzip от Vercel).
- **proxy_cache (зона `vercel_static`, /var/cache/nginx/vercel, 2 ГБ, inactive 7d):**

- **НЕ кэшируется:** `location /api/` (ПДн/динамика, остался с rate-limit TASK-022),
  `location = /api/healthz`, `location /media/` (локальная отдача файла, `expires 30d`).
- **Бэкап:** `/root/nginx-backup-2026-06-09/` (`gpeters.ru.bak` — исходник, `nginx.conf.bak`,

## Решение по HTML-кэшу (обоснование)

HTML **не** микрокэшируем: ответы Next несут `Vary: rsc, next-router-prefetch, …` (RSC-варианты
для prefetch vs полная навигация) и `Cache-Control: max-age=0, must-revalidate`. Микрокэш без
точного ключа по этим заголовкам рискует отдать RSC-payload вместо страницы. При этом Vercel
уже отдаёт HTML со своего edge (`X-Vercel-Cache: HIT`). Поэтому кэшируем только безопасную
immutable-статику и оптимизированные картинки — максимум пользы при нулевом риске.

## Проблемы / открытые вопросы

- **brotli недоступен** в стоковом nginx Ubuntu — только gzip. Если нужен brotli, отдельная мини-задача
  (пакет `libnginx-mod-http-brotli` из стороннего PPA или сборка) — вне объёма TASK-071.
- `/_next/image` кэш форсирован на 1ч поверх `max-age=0` от Vercel: при замене обложки (тот же
  URL) возможен стейл ≤ 1ч — приемлемо для контент-сайта; `proxy_cache_revalidate on` ревалидирует.
