## Что сделано

Тяжёлое hero-видео (9 МБ) снято с критического пути: база — статичный постер,
видео грузится только там, где уместно. Тексты/CTA/композиция hero не менялись.

- **Постер — всегда** рендерится первым (`<Image priority fill>`), это и есть LCP-кадр
  (мгновенно). Раньше постер в видео-ветке показывался только через атрибут `poster`.
- **`<video>` монтируется ТОЛЬКО на клиенте после первого кадра** (`requestAnimationFrame`),
  и только если: вьюпорт `≥768px` (`matchMedia`) **и** сеть не «экономная/медленная»
  (`navigator.connection.saveData !== true` и `effectiveType ∉ {slow-2g,2g,3g}`).
  Иначе — остаётся постер, `<video>` в DOM не появляется → mp4 не запрашивается.
- **prefers-reduced-motion** — как было: только постер (внутри `evaluate()` гасит видео).
- **Без «прыжка»:** постер и видео — один и тот же кадр (старт видео = кадр постера);
  видео абсолютным слоем поверх постера.
- **Безопасные фоллбеки:** нет Network Information API → решает только брейкпоинт
  (десктоп → видео, узкий экран → постер). Слушатели `change` на `matchMedia` и
  `connection` переоценивают условие при ресайзе/смене сети. setState вынесен из тела
  эффекта (в rAF/колбэки) — чисто по `react-hooks/set-state-in-effect`.
