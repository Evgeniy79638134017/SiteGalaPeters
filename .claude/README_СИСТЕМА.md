# Трёхуровневая агентная система: Cowork ↔ Claude в VS Code

> Обезличенный шаблон координационного слоя. Не привязан к домену и стеку.
> Скопируйте папку в новый репозиторий, замените все `[ПЛЕЙСХОЛДЕР]` и `<TODO>`, удалите этот заголовок-предупреждение.

---

## 1. Идея в одном абзаце

Один человек управляет двумя экземплярами Claude. **Cowork** (в Claude Desktop) — это «мозг»: планирует, декомпозирует, пишет промты, проверяет результат. **Claude в VS Code** — это «руки»: получает атомарную задачу, пишет код, билдит, линтит, отчитывается. Связь между ними — **не чат, а git и файлы в папке `.claude/`**. Человек копирует готовый промт из Cowork в VS Code и принимает результат. Никто ничего не держит в голове: всё состояние живёт в файлах.

---

## 2. Три роли

| Роль | Где | Что делает | Чего НЕ делает |
|------|-----|-----------|----------------|
| **Cowork** (Архитектор / PM) | Claude Desktop | Планирует, расставляет приоритеты, пишет промты по 6-компонентной формуле, читает отчёты и верифицирует | Не пишет код, не принимает архитектурные решения за владельца |
| **Claude в VS Code** (Исполнитель) | VS Code | Берёт задачу из `SPRINT.md`, пишет код, прогоняет gate'ы, пишет отчёт и `CHANGELOG` | Не меняет архитектуру сам, не редактирует `BACKLOG.md` без указания |
| **Владелец** (Vision Holder) | Оба | Утверждает план, копирует промт в VS Code, принимает результат | Не делает машинную работу (команды, git, переименования) — это уходит в промт |

Ключевой принцип: **владелец — не диспетчер**. Машинные действия (bash/git/установка пакетов/чтение конфигов) формулируются как промт для VS Code, а не как просьба к человеку. Исключение — только физические действия: ввод паролей, MFA, действия в дашбордах с 2FA.

## 3. Поток одной задачи

```
        ┌──────────────────────────────────────────────────────────┐
        │                       Cowork (мозг)                       │
        │  1. Берёт задачу из BACKLOG.md                            │
        │  2. Декомпозирует до атомарной                            │
        │  3. Пишет промт по 6-компонентной формуле                 │
        │     → файл .claude/prompts/PROMPT_NNN_name.md             │
        └───────────────────────────┬──────────────────────────────┘
                                     │ владелец копирует промт
                                     ▼
        ┌──────────────────────────────────────────────────────────┐
        │                 Claude в VS Code (руки)                   │
        │  4. Читает CLAUDE.md → SPRINT.md → ARCHITECTURE.md        │
        │  5. Пишет код                                             │
        │  6. Прогоняет gate'ы (build / lint / типы / тесты)        │
        │  7. Пишет отчёт REPORT_TASK-NNN + запись в CHANGELOG.md   │
        │  8. Ставит статус [x] в SPRINT.md, коммитит, пушит        │
        └───────────────────────────┬──────────────────────────────┘
                                     │ git push
                                     ▼
        ┌──────────────────────────────────────────────────────────┐
        │                       Cowork (мозг)                       │
        │  9. git pull, читает REPORT + CHANGELOG                   │
        │ 10. Верифицирует против gate'ов (НЕ верит на слово)       │
        │ 11. Принимает задачу или возвращает BLOCKER               │
        └──────────────────────────────────────────────────────────┘
```

Канал связи — **git**, а не пересказ человеком. Cowork читает отчёт напрямую через `git pull` + чтение файла. Это убирает «курьерскую» нагрузку с владельца и исключает искажение при пересказе.

## 4. Карта файлов `.claude/`

```
<repo>/
├── CLAUDE.md                     — корневая инструкция, читают ВСЕ агенты
└── .claude/
    ├── settings.example.json     — разрешения/директории (переименовать в settings.json)
    ├── tasks/
    │   ├── SPRINT.md             — активный спринт + статусы задач [ ] / [x]
    │   ├── BACKLOG.md            — полный бэклог + ВОПРОСЫ/РЕШЕНИЯ (зона Cowork)
    │   └── archive/             — закрытые спринты
    ├── prompts/
    │   ├── PROMPT_TEMPLATE.md    — 6-компонентная формула (эталон)
    │   └── PROMPT_NNN_name.md    — готовые промты по задачам
    ├── reports/
    │   ├── _TEMPLATE.md          — шаблон отчёта исполнителя
    │   ├── REPORT_TASK-NNN_*.md  — отчёты по задачам
    │   └── _archive/            — отчёты старше 30 дней / по закрытым задачам
    ├── logs/
    │   └── CHANGELOG.md          — лог изменений по шаблону
    └── context/
        ├── ARCHITECTURE.md       — архитектура проекта
        └── RESEARCH_*.md         — глубокие исследования PM (по необходимости)
```

Кто что трогает:
- `SPRINT.md` — исполнитель берёт первую `[ ]`, ставит `[x]` при готовности.
- `BACKLOG.md` — **только Cowork**. Исполнитель не редактирует без явного указания.
- `CHANGELOG.md` — исполнитель дописывает запись после каждой задачи.
- `prompts/` — пишет Cowork.
- `reports/` — пишет исполнитель, читает Cowork.

## 5. Шесть компонентов промта

Любой нетривиальный промт от Cowork к VS Code содержит ровно эти блоки. Логика: монолитный промт надёжен как `P(0.8^20) ≈ 1%`, атомарный по 6 компонентам — `95%+`.

1. **Контекст** — что за проект, фаза, релевантные файлы (точные пути), что прочитать перед стартом.
2. **Цель** — один атомарный результат + формальный критерий «готово».
3. **Вайб** — тон подхода («минимальное вмешательство», «защитный refactor») и чего избегать.
4. **Технические параметры** — версии, команды билда/линта/тестов с cwd, где секреты, edge cases.
5. **Visual Guidance** — образец-паттерн в репо («сделай как X в файле Y»), скриншот при UI-задачах.
6. **Ожидания качества** — gate-условия, что писать в CHANGELOG, какой статус в SPRINT.md, DO/DON'T.

Полная формула и пример — в `.claude/prompts/PROMPT_TEMPLATE.md`.

## 6. Верификация встроена в промт

Каждый промт несёт gate-условия. Исполнитель либо проходит все gate'ы, либо возвращает `BLOCKER`. Cowork **обязан** прочитать отчёт перед тем как пометить задачу принятой — не доверять на слово (без независимой верификации ошибки в агентных системах усиливаются многократно).

Базовый набор gate'ов (адаптируйте под свой стек в `CLAUDE.md`):
- сборка без ошибок;
- линтер зелёный;
- проверка типов (если язык типизирован);
- дельта размера бандла зафиксирована (для фронтенда);
- проверки безопасности данных, если тронута БД/доступ;
- превью-деплой зелёный.

---

## 7. Автономность при блокерах

Когда исполнитель упирается в блокер, Cowork: (1) разбирает корень, (2) проектирует 2–3 «ladder»-варианта обхода в одном промте, (3) даёт исполнителю право переключаться между ними сам, (4) эскалирует к владельцу **только** когда все варианты исчерпаны — одним сообщением с кратким summary. Лимит автономии: 2 попытки ИЛИ 30 минут, что раньше.

---

## 8. Как развернуть в новом проекте

1. Скопировать содержимое `_TEMPLATE_coordination_layer/` в корень нового репозитория: `CLAUDE.md` ложится в корень, а папку **`dot-claude/` переименовать в `.claude/`** (она названа так в шаблоне только потому, что инструмент не даёт писать в скрытую папку напрямую).
2. Переименовать `.claude/settings.example.json` → `.claude/settings.json` и вычистить пути/разрешения под новую машину.
3. В `CLAUDE.md` заполнить: домен проекта, стек, структуру, конкретные команды gate'ов.
4. В `ARCHITECTURE.md` описать реальную архитектуру.
5. Открыть `SPRINT-1` в `SPRINT.md`, наполнить `BACKLOG.md`.
6. Найти и заменить все `[ПЛЕЙСХОЛДЕР]` и `<TODO>` по всему дереву.
7. Удалить файлы `README_СИСТЕМА.md` и `_TEMPLATE_coordination_layer`-обёртку, если не нужны в репо.
